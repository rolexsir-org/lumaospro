# Production-polish engineering report

**Date:** 2026-10-28

**Baseline:** `05f80cd` on `arena/f6f4e2b5-lumaospro`; the checkout was clean before this work.

## Fixes and scope

- **Appearance and persistence** — `LumaPrefs.kt`, `ExperienceProfileController.kt`, `OnboardingActivity.kt`, `SettingsViewModel.kt` and `StudioScreen.kt` now apply a Studio draft or experience profile in one preference transaction, report write failures, and wait for the saved configuration before enabling Studio edits. A color-only edit and experience switch preserve customized rows and layouts; an explicit change of Studio layout preset still adopts that preset's default rows. Onboarding initializes defaults only when appearance is genuinely unconfigured. The existing backdrop key gains an explicit `theme_default` value so a nullable selection survives reopening; missing/invalid legacy values still resolve to wallpaper. Older app versions will interpret that new value as their wallpaper fallback.
- **Layout maintenance** — `LauncherViewModel.kt`, `HomeLayout.kt`, `HomeLayoutCodec.kt` and `LumaPrefs.kt` no longer prune placements/history after an empty app scan. Automatic dock seeding and non-empty-scan reconciliation skip noncanonical layouts and use an atomic compare-before-write, so a newer saved layout is not overwritten by stale maintenance work. The ordinary forgiving layout decoder and existing manual editing model remain unchanged.
- **Widgets** — `HomeActivity.kt`, `LauncherViewModel.kt`, `HomeLayoutCodec.kt`, `WidgetHostController.kt`, `WidgetPlan.kt`, `HomeGridAdapter.kt` and the manifest preserve pending bind/reconfigure state during activity recreation, identify the correct widget on reconfiguration, and avoid deleting saved placements when a provider/host lookup temporarily fails. Adds report success after the layout write; duplicate restored results do not delete an existing binding. Explicit cancellations/removals release an ID only after checking in-memory state and a single raw snapshot of legacy, known-profile and other `home_layout_` keys; read failures and noncanonical/unknown layouts retain the ID. The edit-mode resize handle offers a menu as well as dragging, and a cancelled drag restores its original height.
- **Drawer, picker and responsive controls** — drawer filtering avoids launching stale results and exposes a local no-results message without removing web/store actions. The alphabet rail has a larger target and keyboard/accessibility actions. Widget picker grouping no longer drops distinct packages with the same app label. Settings and Studio expose advanced controls progressively, use wrapping/scrolling or stacked controls on constrained screens, and retain the existing glass surfaces and theme identities. Popup menus are bounded to the visible frame and scroll when tall; drawer horizontal system insets are applied. `ThemeCardPalette.kt` uses opaque card colors and contrast-tested text.
- **Build entrypoint** — restored the official Gradle 8.13 wrapper JAR. `build.sh` prefers the provisioned Gradle, uses a complete wrapper as fallback, and only prefetches Robolectric for test/check tasks, deleting partial downloads. `app/build.gradle.kts` points tests at the same cache only when the image exists. No debug-signing fallback or new application dependency was added.

Regression coverage was added or extended for appearance persistence, widget ID safety and resize planning, picker grouping, drawer results, and theme-card contrast. New Robolectric tests cover activity/widget restoration, same-query drawer behavior, resize-handle dispatch, menu bounds, and alphabet accessibility; **they have not been executed**.

## Remaining work and release boundary

1. Provision a complete JDK 17, Gradle 8.13, Android SDK 36 and the declared dependency closure on a networked build host; run the actual Gradle unit/Robolectric suite, lint, debug assembly, release assembly and bundle. Investigate all build/lint warnings and failures, then install the resulting artifacts. The manually substituted checks above do not establish release compatibility.
2. Exercise theme preview/apply/revert/reset and system switching across Pure, Liquid and Midnight; verify persistence after rotation, process death, upgrade and backup/restore. Check narrow/landscape layouts, display cutouts, IME, large font scales, contrast, TalkBack and keyboard navigation on real devices, including API 26 and current Android.
3. Exercise widget consent/configuration/reconfiguration, cancellation, removal/undo, rotation/process death, provider uninstall/reinstall, profile switching, resize and concurrent layout writes. Conservative cleanup intentionally retains IDs when their safety cannot be proven; speculative orphan sweeping is disabled, so host IDs can remain allocated. The transient removal undo opportunity can be lost on recreation. A safe deferred cleanup strategy and device/lifecycle testing remain necessary. Automatic maintenance and ID release are conservative, but normal preference flows still fall back on read errors and manual layout editing still uses the forgiving decoder; edits to damaged layouts need further safeguards and recovery testing. A non-empty app scan is still treated as authoritative, so an incomplete non-empty platform response could remove absent app placements or history; validate or harden that behavior before release.
4. Measure startup, frame pacing, memory and diagnostics on representative devices/OEMs; no performance or visual behavior is claimed verified here.
5. `keystore.properties` is absent. Configure the private upload keystore outside version control and verify the freshly built release artifact and signing identity. No signed release APK/AAB was produced, and this work does **not** establish Play readiness.
